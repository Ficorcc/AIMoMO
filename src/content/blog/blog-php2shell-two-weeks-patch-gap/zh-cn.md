10 月 21 日那场 PHP 安全事件，我两周前写过一次，当时的角度是"责任在主机商，不在你点不点更新"。两周过去，这事的后半场数据陆续出来了，比我预想的更难看。

## 先说结论：这不是"打个补丁就完了"

两个漏洞编号 CVE-2026-109618 和 CVE-2026-109619，安全圈给了个传播性极强的名字：PHP2Shell。CVSS 评分都是 9.2，最高等级。共同点是——攻击者不需要登录，一个构造好的请求就能在服务器上执行代码，拿 shell、读数据库、改文件。

PHP 官方当天就发了 8.2.35、8.3.36、8.4.27、8.5.12 四个修复版，并称这是十多年来 PHP 面临的最严重安全事件。

问题在于，补丁发出来和补丁装上去之间，隔着一条很长很长的路。

## 两周后的战场数据

根据后续披露的信息，几个数字值得盯：

- **约 157 万台主机在补丁发布后仍然暴露**。这不是"没人管"，而是"很多人不知道自己的 PHP 跑在哪"——托管主机、容器镜像、老旧的虚拟主机套餐，PHP 版本往往是服务商控制的，站长根本没有入口。
- **欧洲多国政府站点一度临时下线**。欧盟 CERT-EU、欧盟委员会、欧洲刑警组织联合发声明要求立即排查；加拿大、荷兰的国家网络安全中心同步预警。能让政府把官网拉闸，说明风险评估已经很悲观。
- **攻击者动作比预期快**。安全机构 CYFIRMA 披露，一个疑似与朝鲜关联的攻击组织正在针对全球 PHP 基础设施做侦察，涉及 216 台目标主机，重点盯政府、金融、制造、物流。
- **第三个洞浮出水面**。除两个 RCE 之外，还有一个 session 上传进度相关的 CVE-2026-115560 被公开，同样是 AI 协助发现的。
- **最要命的一条：PHP 8.1 及更早版本没有补丁**。这意味着还跑在这些版本上的站，唯一的出路是升级大版本——而升级大版本对很多老站来说，等于重做。

## 为什么这次不是"WordPress 的事"

这是我最想强调的一点。漏洞不在插件、不在主题、不在 WordPress 或 Typecho 的核心代码里，而在它们脚下的 PHP 解释器。

Wiz 在 WordPress、Drupal、Joomla 上都演示了无需登录的 RCE，但那三个只是验证对象。所有处理 web 请求的 PHP 安装都在风险范围内：PHP-FPM、Apache 的 mod_php、php-cgi、FrankenPHP、LiteSpeed 全都在列，其中 mod_php 风险最高——攻击可以在你的业务代码跑起来之前就完成。

换句话说，**你代码写得再规范、插件装得再少，也挡不住这一层。** 这是过去几年 PHP 生态习惯的"补丁思路"失效的地方：大家习惯了"插件有洞就更新插件"，但运行时的洞，得由控制运行时的那个人来补。

## 站长的实际动作清单

说点能做的。按优先级：

1. **查版本**。在服务器上跑 `php -v`，或者看主机面板的 PHP 版本设置。对照 8.2.35 / 8.3.36 / 8.4.27 / 8.5.12 这四个安全线。
2. **找控制权**。共享主机、虚拟主机用户，你往往不能自己升 PHP，必须开工单问服务商"是否已应用 PHP2Shell 补丁"。问不到明确答复，就当没打。
3. **老版本做决断**。如果你的站还跑在 8.1 或更早，别指望补丁了。要么升级，要么把站迁走，要么至少在 WAF 层加规则挡住异常请求——这是缓冲，不是解法。
4. **静态站的例外**。纯静态（Astro、Hugo、Hexo 之类输出到 CDN 的）不跑 PHP，这次天然免疫。这算不算一条"迁移理由"？我觉得算半条：不是因为这次漏洞要搬，而是这次漏洞提醒了你，运行时的债务是别人在替你还，还不上就轮到你。
5. **别只看主站**。顺手查一下服务器上那些被遗忘的老博客、测试站、插件 demo——这类"僵尸站"才是常年在裸奔的那批。

## 我的判断

PHP2Shell 真正的意义，不是"又一个高危漏洞"，而是**补丁分发的结构性缺口第一次被摆到台面上**。

过去十几年，PHP 生态的繁荣建立在"装个程序就能建站"上。代价是，绝大多数站长对自己脚下的运行时没有任何控制权。漏洞出现在应用层，社区能秒级推送更新；漏洞出现在运行时，就变成了一场需要主机商、CDN、镜像维护者、企业 IT 一起配合的行动——而这套协调机制，现实里是不存在的。

顺带说，这次是两个 AI 模型（GPT-5.6 Sol 和 Gemini 4 Argon）参与挖出来的，其中一个洞在 PHP 代码里藏了十多年没被人工审计发现。发现速度已经被 AI 拉起来了，修复速度还停在人的节奏上。这个剪刀差，会是接下来几年建站圈最现实的麻烦。

所以我的建议很直白：**今天就去问你的主机商一句"PHP 是哪个小版本"。** 答案可能比你想的更糟糕，但至少你能知道自己在哪。
