10 月 8 日，华为宣布了一个对开发者圈挺有分量的事：**DevEco 三件套的鸿蒙 PC 版同步开启公测**。DevEco Studio 从邀测转正、DevEco Code 和 DevEco CLI 则迎来首个公测版本。背景是 HarmonyOS 6/7 的终端规模刚刚突破 9000 万——数字本身不是重点，重点是这三件套的定位：**让 AI Agent 直接长在鸿蒙开发流程里**。

先说三件套的分工，这个设计本身就值得琢磨。

DevEco Studio 是底座。基于华为自研的毕方（BitFun）技术平台，主打快速启动、低资源占用，编辑器核心用 Rust 写，明显是冲着"开发环境本身不能拖后腿"去的。它有一个我很喜欢的细节：不需要装模拟器，就能在鸿蒙 PC 上秒级启动手机、平板、折叠屏三种形态的调试窗口，改一次代码多端同步看效果。对常年被模拟器启动时间折磨的开发者来说，这体验是降维打击。

DevEco Code 才是这次的主角——一个开箱即用的鸿蒙 AI Agent。它内置了 GLM5.3、GLM5.1 模型，集成鸿蒙知识库、Skills 和 MCP 工具，还支持你自己配置第三方模型。安装方式简单得不像华为出品：`npm install -g @deveco/deveco-code`。它有三种工作模式：Plan 模式先给方案让你审，Build 模式人机协作，Goal 模式放手让它干——本质上就是把"AI 写的代码要不要信任"这个老问题，拆成了三个可控档位。它还带了个"UI 意图验证"：自动校验 AI 跑出来的结果是不是你要的，试图解决"AI 说编译过了，其实根本不是你要的那个功能"的经典假象。

DevEco CLI 则是给"外面的 AI"开的口子。一条 init 命令，就能把鸿蒙的官方知识库和 70 多个专业 Skill 部署到你本机的任意 Agent 工具里——工程创建、语法检查、编译构建、推真机、抓日志，全命令行化。也就是说，**你在 VS Code、Claude Code 或者任何别的 Agent 环境里，也能指挥鸿蒙开发**。这个思路我觉得比单独做一个 IDE 更聪明：它不逼你换工具，而是把鸿蒙的开发能力做成可以被任意 Agent 调用的"服务"。

为什么我说这是"鸿蒙 PC 开始自己写自己的应用"？因为它把一条链路彻底打通了：**鸿蒙 PC 既是鸿蒙应用的运行终端，也是原生开发工作站**。以前你写鸿蒙应用，要么用别家的电脑装 IDE，要么在鸿蒙设备上勉强凑合；现在买一台鸿蒙 MateBook，装个 DevEco，就能在上面原生开发鸿蒙应用，还自带 AI 辅助。终端规模 9000 万 + 原生工具链就位，这个组合对独立开发者的吸引力是实打实的——生态的窗口期，往往就开在这种"工具终于齐了"的时刻。

从我一个关注独立开发生态的角度看，这件事还有一层意义：**Agentic 开发范式第一次落到国产操作系统原生体系里**。过去一年我们看惯了 Copilot 在 IDE 里补全代码，但"AI 规划、AI 写码、AI 自检、AI 上机"整条闭环由官方工具链原生提供，鸿蒙算是走得比较前的。DevEco Code 把模型、知识库、Skills、MCP 全部内置，本质上是在替开发者回答那个终极问题：**新应用到底应该是人写的，还是人指挥 AI 写的？**华为的答案是后者——而且它把"指挥"这个动作也做成了产品。

当然，公测阶段还有很多未知数：GLM 写鸿蒙应用的完成度到底如何？真机上架前的那段路 AI 能不能走完？这些要等开发者真正跑起来才知道。但方向已经很清楚：以后写鸿蒙应用的门槛，不是你会不会写代码，而是你会不会把需求讲清楚。

我越来越觉得，生态竞争的下半场比的是"谁先让普通人用 AI 把东西做出来"。鸿蒙这次递出的三件套，算是一张相当有诚意的入场券。
