这周 AI 圈注意力全在大模型「周抛」上，但我更想聊一个不那么炸裂、却和每个做网站的人更相关的动作：Vercel 推出了 design.md。

简单说，它是一份「给 AI 看的设计说明书」。你把一个站点的设计规范写成 design.md，AI Agent 生成页面时就照着来，不再每次都给你生成一套「全网同款」的默认审美。

## 痛点其实人人都遇到过

现在用 AI 写页面、做落地页，最大的尴尬不是「做不出来」，而是「做出来都一个样」。

你让 Cursor、v0，或者任意 Agent 生成一个按钮、一个卡片，它大概率给你一套从中庸审美里采样出来的产物：圆角、阴影、渐变蓝、千篇一律的间距。十个人用同一个工具，做出的站看起来像同一个模板换了个标题。

问题不在模型笨，而在于模型不知道「你这家」长什么样。它没有你的设计语言，只能退化到统计上的平均审美。

design.md 的思路很直白：把「这家公司的设计规矩」显式写下来，喂给 Agent。它配套一份公开样式表和一组评估回路——用人工反馈去纠错、去 refine 那些机械性的失败，比如该对齐没对齐、该统一的间距不统一。

## 为什么这是个有意思的拐点

我觉得 design.md 代表的，是 AI 生成内容从「能生成」走向「可治理」。

过去两年，AI 建站的关键词是「快」：一句话出站、几分钟上线。但「快」的副作用是失控——你没法保证十个页面风格统一，也没法让 Agent 遵守你定下的品牌边界。design.md 把「设计规范」从人脑里、从 Figma 文件里，搬成了一台机器能读的契约。

这对独立博主、小团队尤其有意义。我们没专职设计师，以前靠主题和模板兜底；现在如果能在项目根目录放一份 design.md，AI 帮我改版、加页面时，就不会把整个站带歪。你的博客，终于能保持「你的样子」，而不是「AI 的默认样子」。

## 但别神话它

我也得泼点冷水。design.md 解决的是「一致性」，不是「品味」。它保证 Agent 不跑偏，但写得好不好、审美高不高，还是取决于你写进那份文件的内容。一个自己都没想清楚品牌语言的站长，给 Agent 的也只能是一份糊涂说明书。

而且它本质是「约束」：越详细的规范，Agent 自由度越低。对追求极致个性化的创作者，这可能反而束手束脚。所以它更适合「要稳定输出、要品牌统一」的场景，而不是天马行空的实验。

## 我的判断

design.md 这种「给 AI 立规矩」的小文件，会越来越多。前端、建站领域的下一个战场，不是「谁生成得更快」，而是「谁能把生成管得住」。

对做博客、做独立站的朋友，我的建议是：现在就开始攒你自己的 design.md——哪怕只有十几行，写清主色、字体、圆角、间距和几条「不准」。等哪天你把改版、加栏目的活交给 Agent 时，它会替你守住「这是你的站」这条底线。
