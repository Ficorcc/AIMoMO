10 月 1 日，Cloudflare 干了一件在它身上不太典型的事：开源了两个自研模型。

名字叫 Clef 和 Clef-flash（谱号），Apache 2.0 许可，权重挂在 Hugging Face 上，同时直接跑在它自家的 Workers AI 上。大的是 27B，底座 Qwen3.8-27B，带视觉编码器；小的是 9B，底座 Qwen3.5-9B，两个都是 64k 上下文。

关键在于它们「不是聊天模型」。这是决策模型（decision model）：你给它一段状态（文本、JSON、图片、视频都行），再给一组固定题型的问题（是/否、单选、打分），它一次性返回每个选项的概率，全程不写一个字。

这个品类不算新。9 月中旬我写过 Typesafe 的 Jev，当时它已经是 Vercel AI Gateway 历史上被采用最快的模型。但这一周多事情变得很热闹：9 月 30 日 Liquid AI 发了 d1，10 月 1 日 Cloudflare 和 Amazon 同一天出货（Amazon 是 Strands Decider 2B），上海 AI Lab 的 Intern-Decision 也在同期上架。八天四款，路数还都一样——**一个 agent 如果让 27B 的大模型去写 JSON，就是在为它用不上的能力付钱。**

## 对独立站来说，有用的地方在哪

先说工程上的便利：Clef 完全兼容 Jev 的 API，换的是 endpoint，不是整条集成链路。价格方面，Clef 在 Workers AI 上按输入计费，每百万 token 0.24 美元，Clef-flash 0.09 美元——这两个数字来自媒体转述，Cloudflare 的公告页本身没写价，The Register 拿它对标 Jev 的 0.042 美元，所以别把它当账单承诺。延迟上，Cloudflare 自测 H200 的中位数是 Clef 209 毫秒、Clef-flash 38.8 毫秒，同一个测试里 Jev 是 524 毫秒。38 毫秒意味着「判断」这一下，用户几乎感觉不到是在等一个模型。

具体到独立博客，我能想到的用法有这么几类：

| 场景 | 交给它决定什么 |
| --- | --- |
| 评论审核 | 这条是不是垃圾、要不要转人工复核 |
| 评论分流 | 归到「提问 / 反馈 / 闲聊」，决定要不要通知你 |
| 图片与附件 | 上传的图是不是违规、是不是同一类文档 |
| 表单与工单 | 该走哪个流程、紧急程度打几分 |

以前做这些事，标准套路是调 GPT 或 Claude 让它「输出 JSON」，然后自己解析——贵、慢，还得防着它多写一句解释把 JSON 搞坏。决策模型把「写文字」这一段直接砍掉，只留判断，于是成本降一个数量级、延迟降到几十毫秒；而且它给的是概率：0.93 和 0.55 是两回事，后面那种你可以直接转人工。

## 但也别急着把判断交出去

有几盆冷水得泼：

- **跑分全部是厂商自评。** Clef 的表格来自 Cloudflare 自己跑的 Decision Index 0.2.1（四十多行）。它在分类和路由上确实领先：BANKING77 的 macro-F1 是 94.2，Jev 是 79.7；BFCL 98.5。但换到需要「真推理」的指标就反过来了——GPQA Diamond 48.0 对 Jev 的 78.3，MMLU-Pro 65.9 对 82.7，BBH 73.7 对 92.9。一句话：会分类，不太会想事。
- **独立验证少得可怜。** 目前能看到的一次独立测试只有 42 条决策样本，flash 拿到 66.7%，还输给 Jev 的 71.4%。样本太小，只能算「还没翻车」。
- **自托管不便宜。** The Register 转述 Cloudflare 产品经理的说法：64k 上下文、单并发下，Clef-flash 要 41GB 显存，Clef 要 85GB。想在自己机器上跑，先看显卡。
- **训练数据不公开。** 名字叫开源，开的是权重和代码，不是数据。真正合规敏感的场景，这一点要想清楚。

## 我的判断

这件事对独立站长的价值，不在于「我们也能训模型了」，而在于**边缘平台开始把「小判断」做成基础设施**：一次调用、几十毫秒、百万 token 几分钱，评论审核、表单分流这类事，第一次有了成本上说得通的自动化方案。

如果你的站已经跑在 Cloudflare 上，最小可行路径大概是：写一个 Worker，先用 Clef-flash，把评论审核接上去，跑一周，只看两个数字——误杀的条数和漏掉的条数。这两个数字比任何基准表都更能说明它值不值得留在你的流水线里。

至于那个更诱人的念头——把所有「要不要」都交给它——先忍住。概率是好东西，但决定还是要握在自己手里。
