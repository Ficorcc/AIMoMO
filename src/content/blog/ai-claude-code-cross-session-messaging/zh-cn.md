你可能习惯了这样的工作方式：开一个 Claude Code 会话写前端，另一个会话调后端 API，两个窗口来回切换。遇到问题时，只能靠手动复制粘贴对话内容来「传话」。

但 Claude Code 在 8 月 7 日发布的 2.1.224 版本，把这件事彻底改写了——两个独立的 Claude 会话，现在可以直接「聊天」了。

## 会话隔离的传统被打破

从 AI 编程工具诞生那天起，「会话隔离」就是基本设计原则。每个会话有独立的历史、独立的文件访问权限、独立的工作记忆。这个设计出于安全和隐私考虑，但也带来了真实的协作成本：当两个会话在同一个代码库的不同模块工作时，彼此无法感知对方做了什么。

Claude Code 这次推出的 ListAgents 和 SendMessage 两个新工具，改变了这个局面。它们让同一台机器上运行的两个 Claude Code 会话可以通过本地 socket 直接通信，不需要经过 Anthropic 的服务器。消息传输完全是本地的，不涉及任何云端中转。

更有意思的是，你不需要手动调用这两个工具——Claude 会自己判断何时需要向另一个会话发送消息，或者主动触发通信。

## 什么时候 Claude 会「自己发消息」？

根据官方文档，Claude 会在两种场景下主动发起跨会话通信：

**场景一：一个会话的改动影响到了另一个会话的工作**

想象你在做前端重构，Session A 正在修改 API 接口格式，Session B 在写对应的前端调用代码。传统模式下，Session B 只有在测试失败后才会发现问题。而有了跨会话通信，Session A 可以在改动落地前主动通知 Session B：「接口字段改了，记得同步更新前端代码」。

**场景二：一个会话解决了另一个会话正在卡住的问题**

Session A 在调依赖冲突，卡了一小时。同一台机器上的 Session B 刚好在另一个模块里处理过同样的依赖问题，已经找到了解决方案。现在 Session B 可以直接把解法发给 Session A，不用你手动在两个窗口间复制粘贴。

这种「主动通知」的能力，让 AI 编程从「异步协作」变成了「实时同步」。

## 三个真实的协作场景

我尝试了几个典型场景，发现这个功能带来的改变比想象中更深远：

**场景一：并行重构和测试**

Session A 在重构代码，Session B 在跑测试。以前，测试失败后你需要手动把报错信息贴给重构的会话看。现在 Session B 可以在测试跑通后主动通知 Session A：「你改的那块代码测试过了，没问题」或者「测试挂了，具体报错如下」。

**场景二：多模块并行开发**

前端和后端同时开发一个功能时，两个会话可以保持实时同步。后端改了接口字段，前端会话立刻收到通知；前端发现接口调用有问题，也可以直接反馈给后端会话。这比在 Slack 里来回发消息高效得多。

**场景三：Code Review 的「审查员+验证者」模式**

一个会话做代码审查，另一个会话做具体验证。审查会话发现潜在问题后，可以直接把问题发给验证会话去复现和修复，验证结果再自动返回给审查会话。整个过程形成闭环，不需要人工中转。

## 限制也很明显

当然，这个功能不是万能的。几个重要的限制需要知道：

**仅支持文本消息**：你不能在会话之间传递文件、代码块或整个对话历史。消息就是一段简短的文字——一个改动摘要、一个测试结果、一个问题或答案。如果需要传递大量上下文，还是要靠共享文件或 CLAUDE.md。

**仅支持同机通信**：跨会话通信基于本地 socket，意味着两台机器上的会话无法互相通信。如果你的团队在各自的工作站上跑 Claude Code，这个功能帮不了你们。

**仅支持 macOS 和 Linux**：Windows 用户（不包括 WSL 2）目前不在支持范围内。

## 一个更深层的变化：200 子代理限制取消

除了跨会话通信，2.1.224 版本还悄悄取消了每个会话最多 200 个子代理的限制。这对长时间自主运行的 Agent 会话是个好消息——以前跑到一定规模会自动停止，现在可以持续下去了。

同时修复了一个沙箱路径穿越漏洞：使用尾部斜杠的规则（如 `denyRead: "~/.aws/"`）在 Linux 和 macOS 上之前可以被绕过，现在已经正确执行。

## 我的判断：从「单线程」到「多线程」

我一直把 AI 编程工具理解为「智能助手」——你给它任务，它给你结果。但 Claude Code 的这次更新，让我重新思考了这个定位。

**子代理是「垂直」的深度**：一个会话可以派生出多个子代理，层层递进地完成复杂任务。

**跨会话通信是「水平」的广度**：多个平行的会话可以互相协调、互相通知、互相协助。

这两个能力叠加在一起，AI 编程工具正在从「单线程助手」变成「多线程协作系统」。你不再是在和一个 AI 对话，而是在协调一群 AI 的工作——它们各自负责不同的模块、不同的任务，但可以实时同步、互相协作。

这种模式的成熟，可能比参数规模的提升更值得关注。毕竟，真实世界的软件开发从来不是单线程的。
