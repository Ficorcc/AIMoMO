11 月 5 日，Astro 发了 7.4.7。这是一次纯补丁发布——没有新 API，没有新实验特性，官网首页也还是那套宣传文案。但把 release notes 一条条看完，我觉得比很多"大版本预告"更有信息量，因为它暴露的是自建博客在真实运行环境里会踩的坑。

顺手交代下版本坐标：Astro 7.0 是 6 月 22 日，7.4 是 10 月 15 日，7.4.7 落在 11 月初，最低 Node 要求 22.22.0。7 这条线的主旋律是构建速度和工具链收紧——Rust 重写的编译器、Vite 8 + Rolldown、`astro build --timings`。

## 补丁一：反向代理的转发头，终于被联合校验了

这次改动最实质的一条在 `security.allowedDomains`。以前 Astro 是**逐个**校验 `X-Forwarded-Proto`、`X-Forwarded-Host`、`X-Forwarded-Port` 的，现在改成三者**联合**校验：

- 转发的协议，只有在该主机对应的条目允许时才生效；
- 转发的端口，只有该主机条目里列了这个端口才生效；
- 有转发主机但没有转发协议时，用服务器自身的协议来校验；
- 条目里写 `port: "443"`（http 则是 `"80"`）现在也能匹配不带端口的主机名。

还修了一个更细的漏洞：当列表里混用"带协议"和"不带协议"的写法时，旧逻辑会接受 `ftp`、`ws` 这类非 HTTP(S) 的协议值。同时 `Host` / `X-Forwarded-Host` 的校验也收紧了，只接受纯主机名加可选端口。

为什么这条对博客重要？因为绝大多数自建站都挂在 Cloudflare、Nginx、Caddy 或某个 PaaS 后面，`allowedDomains` 是你能拦住 Host 头注入、缓存投毒这类问题的主要开关。如果有站点开了 on-demand 渲染（做搜索、评论、OG 图片生成），这条补丁就属于"必须升"。

## 补丁二到五：都不致命，但都很烦

剩下的几条小修，全是那种不修也能跑、修了才知道原来一直不对的类型：

**畸形百分号编码路径返回 400。** 以前 dev server 和静态预览收到 `%` 开头的坏编码路径，会一路冒泡成 500。500 意味着"服务器内部出错"，而实际是客户端发错了请求。现在老老实实返回 400。别小看这个改动——本地调试时被一堆 500 噪音糊住，很容易掩盖真正的问题。

**`astro check` 会说真话了。** 装是装了 `@astrojs/check`，但加载时抛异常，旧行为是提示你"没安装"，于是你 `npm i` 三遍也没用。现在直接展示原始错误。

**构建不再删别人的文件。** `astro build` 之前会把 Vite 用 `build.license` 选项生成的 license 文件一起清掉，现在只清理 Astro 自己那份 Vite manifest。这条对个人博客几乎无感，但公司项目里如果用 license 合规扫描，产物缺文件是会被审计卡住的。

**同一个对象展开到 scoped styles 元素上，class 会一直长。** 如果某个常量对象（比如从别的模块 import 进来的）被 spread 到带 scoped styles 的元素上，每次渲染这个对象的 `class` 都会增长一次。对静态构建一次性渲染没影响，对长期运行的 Node 服务就是慢性膨胀——跑一晚上，HTML 里的 class 串长得没法看。

## 我更在意的其实是另一半：生态还停在 6.x

看完补丁，顺手翻了圈社区主题的版本状态，感受比较复杂。

Astro 7 的 Rust 编译器比旧的严格得多：未闭合的标签现在直接报错，而老编译器会默默帮你修好。这个改动我举双手赞成——静默修 HTML 是技术债的源头。但代价是升级变难了：一批常见的免费博客主题还停在 6.x 甚至 5.x，有些最近一次提交还是几个月前。主题作者不跟进，跟着升的人就得自己 patch。

所以给同样用 Astro 写博客的人一句实话：**升级成本主要不在框架，在你选的那套主题。** 挑主题时除了看颜值和功能，值得多看一眼 `package.json` 里的 Astro 大版本和最近一次 commit 时间。一个停在 5.x 的主题，你未来每一次升级都得替它的作者干活。

## 我的判断

这次 7.4.7 让我确认了一件事：Astro 已经过了"功能战争"的阶段，进入维护期的样子——补丁里不再有让人兴奋的新玩具，全是安全边界和正确性。对一个写博客的框架来说这是好事，稳比新重要。

具体到行动，我的建议分两档：

- 如果你是纯静态托管（GitHub Pages、Cloudflare Pages、Vercel 静态）、没开 on-demand 渲染、也没动过 `allowedDomains`，那这次补丁对你的实际影响很小，但既然里面有一个真实的安全校验缺陷，顺手升掉不亏；
- 如果你在反向代理后面跑了 SSR 端点，或者用了 `allowedDomains` 做域名白名单，**这条补丁必须上**，别等。

升级路径还是老一套：`npx @astrojs/upgrade`，然后跑一次 `astro build --timings` 对比前后耗时，最后把 dev、preview、生产三种环境各点一遍。十来分钟的活，比事后查 Host 头问题便宜太多。
