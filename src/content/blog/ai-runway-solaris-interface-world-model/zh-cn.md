昨天刷到一个演示视频，让我愣了好几秒。

演示里，用户在一个空白浏览器里随手点击了一个按钮的位置，模型直接生成了一个完整的按钮界面；用户拖动了一下侧边栏，模型立刻生成了侧边栏滑出的下一帧——整个过程没有任何HTML、CSS、JavaScript代码参与，只有"点一下，生成下一帧"。

这个产品叫 **Solaris**，来自 Runway，就是那个做视频生成模型的团队。

## 它是怎么工作的

简单说，Solaris 是基于 Runway 现有视频模型 Gen-4.5 改造出来的，但工作方式更像"逐帧自回归预测"。它的核心思路是：**把界面当成视频来生成**——用户每做一次操作，模型不是去调用某个函数，而是预测"这之后界面看起来应该是什么样"，然后直接渲染出来。

整个系统里有两层模型在协作：
- **语言模型负责推理**：理解用户刚才做了什么、接下来想做什么
- **世界模型负责渲染**：根据推理结果，生成下一帧的界面像素

Runway 还用了少步蒸馏（few-step distillation）和自生成结果训练（self-generated outcome training）来提升速度，据说在 720p 分辨率下已经能做到实时交互。

## 数字看起来不错

官方给出了两轮人类对比测试的数据：
- 指令遵循（你的操作是否被正确执行）：**61% 偏好率**，明显高于代码方案
- 行为自然度（界面变化看起来是否合理）：**71% 偏好率**，也是明显优势

我比较关心的是"明显高于代码方案"这个说法——这里对比的是传统方案，即开发者预先写好代码、模型只是做 UI 适配的方案。从这个对比来看，Solaris 的优势在于**泛化能力**：代码方案只能处理开发者预先想到的场景，Solaris 遇到新操作可以自己"推理"出来。

## 为什么这件事值得写

有几个原因。

**第一，它改变了 UI 生产的瓶颈**。传统方式下，一个新功能从设计到上线，要经过产品→设计→前端→后端一整套流程。Solaris 指向了一种可能：设计师或者产品经理直接"演"出界面，模型生成可交互的原型，不需要写代码就能拿到可用的东西。当然，这里有大量细节问题要解决，但它展示了一个方向。

**第二，它对 Browser Agent 的训练很有意义**。现在 AI Agent 操作浏览器，本质上还是让 Agent 去理解 DOM 节点、发送 JavaScript 操作指令。这要求 Agent 对每种界面都做适配。Solaris 的世界模型提供了一个天然的**泛化训练环境**：Agent 在一个模型生成的界面里操作，能接触到的界面种类远多于真实网站。相当于有一个无限的"界面健身房"。

**第三，它的技术路径很有意思**——不是让 AI 去"理解代码"，而是让 AI 去"理解界面应该长什么样"。这两条路线的长期竞争，可能决定了未来 AI 生成 UI 的上限。

## 我的判断

Solaris 现在肯定还不是能直接用的生产工具。实时720p生成的稳定性、准确性，以及如何和真实业务逻辑（不只是视觉效果）打通，都还有很长的路要走。

但它让我想到了一件事：过去几年，我们已经习惯了 AI 能生成文字、图片、视频。下一个被"生成"的东西，很可能就是**界面本身**。当生成速度够快、质量够好、成本够低，"写代码做界面"这件事会不会就像今天"手写HTML"一样，变成一种极少数人还在做的事情？

不好说。但 Runway 迈出了这一步，我觉得值得关注。
