11 月 5 日，月之暗面把 Kimi Hosted Agents 正式发布了。9 月它还在 Beta，只对国内企业认证用户开放，现在对外全面放出。

大多数人会把这个消息读成「Kimi 也做 Agent 平台了」。我觉得真正值得看的是那张定价表。

## 卖的不是模型，是「让 Agent 一直活着」

先说它到底交付了什么。官方叫 Kimi Durable Harness，说白了就是包在模型推理 API 外面的一层运行与编排系统：会话历史、云沙箱、失败恢复、超时重试、多智能体编排，7×24 托管。你用网页控制台、命令行或者 API 都能进。

上面接的东西也不少：140 多项技能、30 多个插件，插件里有万得、同花顺 iFinD、标普全球这类金融数据源，还首批放了 8 个金融 Agent 模板——投研建模、IPO 跟踪、持仓监控、监管判例日报、基金对账。企业可以用它做两种东西：一种是接内部系统，跑业务监控和运维响应；一种是嵌进对外产品，做投研助手、客服助手。

然后是安全那一块。Kimi Inference Hook 会在每次模型推理之前，检查任务输入和工具返回的内容，按企业自定义的规则放行或者拦截敏感数据。这个组件只定向开放给企业认证用户，个人开发者暂时碰不到。

## 那张定价表才是新闻

托管智能体的费用 = 沙箱运行时长 × 0.072 元/小时 + 模型推理费用 + 插件调用次数 × 单价。

按官方给的估算，一个云沙箱连续计费 30 天，光运行时长就是 51.84 元，不含推理和插件。插件从每次 0.001 元到 0.45 元不等：联网搜索 0.03 元，搜图 0.045 元，部分金融数据插件 0.35 或 0.45 元一次。

过去我们用 API，心智模型只有一个：花多少钱 = 用了多少 token。现在这个等式裂成了三块——**想得多贵、活得久贵、跟外部世界说一句话贵**。

我认为这个变化比功能清单重要得多。token 计价天然鼓励「一次想清楚」，而「沙箱时长 + 插件次数」计价鼓励的是另一套行为逻辑：Agent 在线越久越值钱，工具调得越多越值钱。这不是厂商在坏，这是计费单位在塑造产品性格。

我甚至有点担心这种激励的副作用。真正好用的 Agent，应该是该查就查、查完就收，一次把事办干净；而按小时和按次收费的结构，会让产品团队下意识地偏好「常驻」「长会话」「多轮工具调用」这些指标。企业采购的时候当然也要算总账：一个挂着不动的沙箱，一个月五十几块，看着便宜，但乘上几十个业务 Agent、再乘上推理和插件，账单能长成什么样，现在谁都说不清。

顺带说个对照：Salesforce 在 2024 年 10 月就把 Agentforce 按「每次对话 2 美元」卖，逻辑是按结果收；Kimi 这次是按资源收。前者听起来体面，但对低频场景极不友好；后者透明，但把「运维焦虑」打包卖回给了客户。两条路都还没被验证。

## 为什么这件事值得留意

我觉得有一个信号很明确：**Agent 的竞争重心正从「模型多聪明」往「运行时多可靠」移。**

长程任务的痛点从来不是模型不会想，而是跑到第 40 分钟断了、插件超时了、上下文丢了、重试之后重复扣款了。这些东西模型厂商以前丢给开发者自己搭，现在开始标准化、托管化、按小时卖。对没有基础设施团队的中小公司，这是实打实的门槛下降；对已经自建了一套编排的公司，这是要不要换掉自己半年的工程投入的问题。

另外，Kimi Inference Hook 这个设计方向我挺认可。Agent 最大的隐患是它能读的东西太多——内部文档、数据库、聊天记录，一旦被工具返回的内容里藏了诱导指令，模型就可能照做。在推理前做一次输入和返回的双向拦截，比事后审计有意义。可惜目前只给企业认证用户，个人博客这种小场景用不上。

## 我的判断

托管 Harness 会变成标配，明年这时候几乎所有国内模型厂商都会有一份，价格会打得比现在更凶。真正的分水岭不在价格，在两件事：一是失败恢复到底靠不靠谱——断点续跑、幂等重试、扣费能不能对上账；二是插件生态的质量，30 个金融插件看着热闹，但每次 0.45 元的数据源如果返回脏数据，Agent 越努力错得越离谱。

如果你在评估要不要上，我的建议是先拿一个「跑 20 分钟以上、需要调 3 次以上外部接口」的真实任务去压测，别用 demo。计费表上那三个数字，只有在这种任务里才会露出真面目。
