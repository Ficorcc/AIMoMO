这周看到一篇挺实在的实测：有位博主没按"氛围"选托管平台，而是把**同一个仓库、同一份静态产物**（42 个页面、约 1.1MB 资源）同时部署到 Vercel、Netlify、Cloudflare Pages 三家的免费额度上，接着两周的真实流量（来自 Hacker News 和 dev.to），然后逐项量。

我一直觉得这种"笨办法测评"比任何对比表格都有价值——因为免费额度的坑，从来不在参数表上，而在你撞到它的那一天。

## 数字：亚太的差距不是一点点

他从美东、欧洲、亚太三个区域各打 20 次 `curl`，冷缓存状态下的 TTFB 中位数：

- 美东：Cloudflare 38ms / Vercel 89ms / Netlify 121ms
- 欧洲：Cloudflare 41ms / Vercel 102ms / Netlify 134ms
- **亚太：Cloudflare 64ms / Vercel 287ms / Netlify 342ms**
- p99 最差值：Cloudflare 210ms / Vercel 891ms / Netlify 1204ms

美东和欧洲的差距还能说"都够用"，亚太那一栏就是**三到五倍**了。原因也不神秘：节点数量差着一个量级。Cloudflare 官方数据是 335 个城市、125 个以上国家（含中国大陆），而另外两家的边缘节点分布要少得多。

对我们中文博客来说，这一栏才是最该看的一栏。你的读者大概率不在美东。

## 真正咬人的，不是带宽，是那些冷门配额

那位博主两周里唯一真正撞上的墙，是 **Netlify 的 300 构建分钟/月**。他的 Astro 站构建约 90 秒，听起来毫无压力——直到进入密集迭代期，改主题、调样式、修错字，一天推十几次，第二周就撞顶了。

这就是免费额度最容易被误判的地方：大家都盯着带宽，但带宽通常是最不容易超的那一项。真正的限制往往长这样：

- **Vercel Hobby**：100GB Fast Data Transfer、10GB Fast Origin Transfer、1M 边缘请求、1M 函数调用、4 CPU 小时的 Active CPU、360 GB-小时内存、5000 次图片转换、每天 100 次部署、运行时日志只保留 1 小时。其中 **Fast Origin Transfer 只有 10GB**——一个缓存没配好、图片没优化的站，会在离 100GB 还很远的时候先撞到这一项。
- **Cloudflare Pages Free**：站点数、带宽、静态请求都是"无限"，但**构建只有 500 次/月、1 个并发、单次 20 分钟超时**，每站 20,000 个文件、单文件 25MiB 上限，每账号 100 个项目。Pages Functions 走 Workers 的免费额度，10 万请求/天。
- **Netlify**：那 300 构建分钟。

Cloudflare 计的是"构建次数"而不是"构建分钟"，所以你 15 秒的构建和别人 90 秒的构建成本一样——这反而对慢构建的站更友好。而 Vercel 每天 100 次部署对个人博客基本够用。

顺便说一句，Cloudflare Pages 免费档还自带 Web Analytics，Vercel 和 Netlify 的分析功能都是每月九块十块美元的加购项。为了看自己的访问量而付月费，这事儿说不上多合理。

## 我最想让你注意的，是那条条款

上面那些都是数字，数字超了可以优化。但有一条不是数字，一旦踩了没法优化：

**Vercel Hobby 仅限个人、非商业用途。**

而 Vercel 对"商业"的定义相当宽：为参与制作的任何人带来经济利益的部署都算。收访客的钱、给自己的产品或服务打广告、挂 Google AdSense、以联盟链接为主要目的，甚至**放一个捐赠按钮**，按 Vercel 自己的措辞都落在商业使用的范围里。有人替客户做了个落地页停在自己的 Hobby 账号上，即便一个月只有几百次访问、离任何配额都远得看不见，条款上已经违规了。

这条限制最阴的地方在于：**它不会出现在仪表盘上**。没有黄色进度条，没有邮件警告，只在某天有人审核账号时才浮出水面。

还有一个行为差异也值得知道：**Hobby 超限的处理是"暂停"，不是"计费"。** Pro 是超了继续服务、月底给你账单；Hobby 是超了直接停，多数情况下要等 30 天周期过去才能恢复，而且你没法花钱买额度救急。

对钱包来说这是保护——你永远不会在 Hobby 上收到惊喜账单。但换个场景就是灾难：假设你某篇文章正好被推上首页，流量涌进来，撞顶了，站就黑了。**最需要它活着的那一刻，它恰好挂掉。**这就是"免费"这两个字里，藏得最深的一笔成本。

## 一个背景：平台的重心早就不在你身上了

我顺手翻了一下 Vercel 最近的更新流水：Deployment Storage（保留部署文件、支持即时回滚和保留策略）、生产与预览流量的常驻链路追踪（always-on tracing）、CLI 增加 DNS / 域名 / 项目管理命令组、v0 应用接入上百个第三方服务、AI Gateway 一批模型上下架和促销……

节奏很快，但方向很清楚：**面向团队、面向 Agent、面向企业**。个人免费档在这张路线图上不是重点，甚至可以说是历史包袱。这不是指责——一家公司当然要服务付费客户。但作为使用者，你得清楚自己站在这张图的哪个位置。

十一天前我写过免费图床说跑就跑的事，今天这篇其实是同一个逻辑往上游走了一层：**图床会跑，托管平台的免费额度也会变**。免费额度不是承诺，是"平台此刻的慷慨"。慷慨是可以收回的，而且收回时通常不会提前跟你商量。

## 我的做法

所以我这几年的策略越来越简单，就三条：

**第一，把退出成本压到最低。**内容是 Markdown、放在 Git 里，域名自己在注册商手上、DNS 独立可迁。这样换平台就是"重新 build 一次 + 改一条 DNS 记录"，一小时的事。整个赌注就变小了——赌错也不疼。

**第二，商业属性的站别赌在 Hobby 上。**只要你的站牵着钱——广告、联盟、接单、甚至只是一个赞赏码——就别用免费档。不是配额问题，是**你有没有资格待在这个档位**的问题。这种问题不会给你缓冲期。

**第三，把缓存当成免运费的额度扩容。**那位博主的 OG 图接口返回 `cache-control: public, max-age=604800, immutable`，图片实际只生成一次、之后一整周都由 CDN 兜着，真实调用量远低于浏览量。他那句总结我很认同：**你在函数前面加的每一层缓存，都是一张你永远收不到的账单。**

如果非要给个结论：**个人纯静态博客、读者在亚太，Cloudflare Pages 目前是我会推荐的默认答案**——无限带宽和免费分析这两条，让它是唯一一个我敢押注长期成长的免费档。深度用 Next.js 的选 Vercel，但要清楚"免费"在这里更像试用期。Netlify 在 2026 年确实有点卡在中间，那 300 构建分钟会是你第一个想放弃它的理由。

不过说到底，比"选哪家"更重要的是：**别让你的博客只有一个能活的地方。**
