9 月 18 日，华为全联接大会 2026 期间，HDD·HarmonyOS 创新论坛（HarmonyOS 7 专场）在上海办了一场。看议程像是技术布道，但真正有信息量的部分，是它把「应用怎么被用户找到」这件事，重新定义了一遍。

这场论坛讲四件事：应用 Agent 与 Skill 开发、AI 能力开放、鸿蒙星河互联、空间计算与 AI 辅助开发。

对独立开发者来说，前两块是重点。

## 一、应用 Agent 化 + Skill 化：小艺不再只是入口，是调度员

华为终端小艺产品总监给的路径很清楚：小艺开放平台提供端侧、云侧等多种接入模式，配套开发、调测、管理和分发能力。开发者可以**通过 A2A 协议接入应用智能体**，也可以**用自然语言对话开发 Skill**，或者导入已有 Skill。

系统 Skill 和生态 Skill 还能组合编排，去完成「日程查询 + 出行提醒」这种多步骤任务。

现场最有说服力的案例来自支付宝。支付宝的「阿宝」负责专业服务执行，小艺负责理解意图和服务分发，两边通过支付宝的 AHA 协议体系做 A2A 协同。按支付宝的说法，到今年 9 月底，双方合作会支持政务、医疗、车主、教育等领域 **70 多个服务场景直达**，连「帮我收一下蚂蚁森林的能量」这种小需求都能一句话完成。

这里的关键词不是「智能」，是**分发**。

## 二、分发逻辑变了：不再拼排名，拼的是「被调用」

原文里有一句表述值得琢磨：过去是「用户找 App」，几万个应用争排名、竞价推荐位；新的逻辑是「用户说需求，系统找服务」。

如果你的服务在 Agent/Skill 适配上做得顺，小艺会在用户需求匹配时主动调用你。

反过来读一遍就很清醒：**如果你的服务不能被调用，你在那个入口里就不存在。** 没有排名截图，没有曝光数据，只有「有没有被系统选中」。

对做网站、做独立产品的人来说，这是这几年最值得盯着的一次结构性变化——上一次有类似感觉，大概是小程序刚出来那会儿：一个新的、自带流量的入口，和一套你必须服从的接入规则。

## 三、对开发者最友好的其实是 DevEco CLI

论坛上还发了两件开发工具：DevEco Code 和 DevEco CLI。

DevEco Code 是一站式的鸿蒙应用 AI 开发工具，内置模型服务，集成了鸿蒙知识、Skills 和 MCP 工具，分 Goal、Plan、Build 三种模式。Goal 模式最激进：你用自然语言描述需求和验收标准，确认方案后，AI 自己走完需求澄清、方案生成、编码、语法检查、修复、编译构建、推送模拟器、功能自验证，直到满足验收标准再交给你确认。

但我觉得对普通开发者更重要的，是 DevEco CLI：它提供原子化能力，让**第三方主流 AI Coding Agent 可以直接调用鸿蒙知识资源**，接进你现在的工作流。

这句话的实际含义是：鸿蒙不再要求你先换一套 IDE、先学会 ArkTS 全家桶，"用 AI 写鸿蒙"这条路变短了。对一个还在观望的独立开发者来说，观望成本降下来了。

另外两个补充信息：HarmonyOS 7 新增和升级了 10 余项 AI 开放能力（端侧多模态信息抽取、屏幕识别、图像超分、文搜图、人脸检测等），提供 AI 控件和原子化 API 两种接入方式；鸿蒙星河互联围绕「更快、更智能、更开放」升级，投屏、投播这类操作可以结合全场景 Skill 一句话直达。

## 我的判断

三句话。

**第一，这是一次入口再分配，不是一次功能更新。** 系统级 Agent 掌握意图理解，等于掌握了流量的分配权。谁的 Skill 覆盖的场景清晰、调用稳定性好，谁就更容易被选中。这跟以前优化 App Store 关键词是完全不同的一门手艺。

**第二，红利和风险同源。** 入口集中在一家手里，调用规则、分发权重、审核标准都不透明。你要吃这波「被调用」的红利，就得接受平台依赖——和十年前做公众号、五年前做小程序是一模一样的剧情。

**第三，与其追平台，不如先把「可被调用」这件事做扎实。** 接口清晰、意图边界明确、权限最小化、输出可验证。这套东西放在鸿蒙里叫 Skill，放在别的地方叫什么都不重要——未来的软件分水岭，是它能不能被 Agent 当成一个可靠的工具来调用。

至于独立博客和静态站，短期影响不大。但如果你手里有查询工具、预约服务、内容检索这类东西，值得早点想清楚：它能不能被一句话叫起来。
