11 月 9 日，Automattic 公开了一个新东西，叫 Spacefast。它不是 WordPress 的新版本，也不是又一个 AI 建站器，而是从 Automattic 里独立出来的一家公司。

官方那句定位写得很直白：Spacefast 不是 AI builder，它是给你已经在用的那些 AI 提供基础设施——ChatGPT、Claude、Muse、Grok Bot，还有 Claude Code、Codex、Cursor 这类编码智能体。

## 它解决的其实是一个很土的环节

现在的状态大家都熟悉：AI 一个下午就能把东西做出来，然后麻烦开始了——找托管、开数据库、配登录、绑域名、想清楚谁能访问。这些活儿没有一件是"做东西"的一部分，但每一件都能把热情浇灭一半。

Spacefast 的用法是：把 Spacefast 接到你常用的 AI 上，跟它说"把这个项目放上去"。几秒后，聊天里出现一个链接。全程不用打开后台，也不用离开编辑器。

拿到的东西包括：托管、自己的域名、一个 SQL 数据库，应用内登录"即将上线"；API、CLI、MCP server 三件套，习惯终端的人直接 `npx spacefast publish`；默认隐私，可以密码、邀请、分享链接，或者干脆公开。免费个人计划也有。

## 真正值得看的是这一句

官方说明里，我最在意两条：

**每次发布都生成一个新版本，每个版本有自己的永久地址，随时可以回滚，也可以链到旧版本。**

**对敏感操作（比如回滚、改 DNS）有审批检查。**

第一条改变的是"发布的单位"。传统托管里，发布的结果是"站点变了"——你只有一个当前状态，历史状态要靠备份勉强还原。Spacefast 把每次发布都固化成一个有永久地址的版本，于是任何一次发布都可以被引用、被审查、被退回，而回滚不是"恢复备份"，只是"指向另一个版本"。

对靠智能体干活的人来说这是必需：agent 的迭代频率远高于人，一天发二十版很正常，没有版本坐标系，"哪一版是能用的"会立刻失控。

第二条更值得说。回滚和 DNS 变更都不可逆、影响面大。Spacefast 没有指望模型自己"记得小心"，而是把这些动作挪到平台层，加了审批。这是一个很务实的分工：**能用工程约束解决的问题，不要交给提示词。**

## 底层是老基础设施，定价挺清醒

Spacefast 跑在 WordPress.com 和 Tumblr 同一套基础设施上，官方给的数字是月均 150 亿次以上页面浏览、二十年可用性和安全积累。

定价上它只收基础设施费，不收 AI credits——推理的钱你已经在自己的 AI 那边付过了，它不重复收一遍。它还特意强调：项目跟着你走，下个月换一家 AI，站还留在原地。这个设计看着是小事，实际上是在赌用户会同时用好几个模型。

## 来历比产品本身更有意思

Spacefast 出自 Automattic 今年的"Radical Speed Month"——暂停全部路线图一个月，所有人做自己想做的事。创始人 Batuhan İçöz 当时在 Beeper 团队，非技术背景的朋友不断发来自己用 AI 做的项目，问他 GitHub 怎么弄。他觉得公司的基础设施能给这些项目一个家，就先做了个静态托管；用户开始要后端，他就继续加。9 月软启动，随后独立成公司。

这个路径说明了一件事：需求不是从产品规划里长出来的，是从"身边人卡在哪"长出来的。

## 我的判断

第一，它不是 WordPress 的替代品。有人已经这么解读了，我觉得不准确。它更像"原型托管层"：适合用 agent 做的工具、看板、内部小应用、要私密分享给客户的演示。一旦项目需要内容体系、表单、SEO、多作者协作，还是该回到 WordPress 或 Astro 这种正经建站方案上。原型和成品之间本来就需要过渡带，以前这个带子是空的。

第二，对做独立博客的人，它提示了一种姿势：**把发布当成产生快照，而不是覆盖现场。** 静态站其实天生适合这么干——每次构建产物就是一份不可变快照，只是过去我们懒得给每一份留地址。以后的内容站，"每次改动留一个可引用的版本"可能变成默认操作，尤其当写东西的人从人变成人加 agent 的时候。

第三，隐忧也很具体。评论被设计成"可以直接交付给你的 agent 去改"，这意味着页面上的文字会成为 agent 的输入——那评论就成了一个注入面。托管独家、密码分享不等于权限体系、免费额度的边界在哪，官方都还没细说。

总的来说，Spacefast 值得关注的不是"Automattic 也做 AI 了"，而是它把两个老问题摆到台面上：发布该怎么版本化，不可逆操作该由谁把关。这两道题，不管你做不做 AI 项目，迟早都要答。
