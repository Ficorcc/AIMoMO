上周三（8月28日），htmx 发布了 4.0.0 版本。

如果你没听说过 htmx——它是一个 JavaScript 库，核心理念是让你直接在 HTML 标签里写请求行为，而不是用 JavaScript 写一整页的逻辑。简单说：你在一个链接上加个 `hx-get`，它就会自动发请求、替换页面某个部分，不需要写任何 JS。

这个理念听起来很简单，但它的意义远不止「少写几行代码」。

## 4.0 改了什么

htmx 4.0 的核心变化是**底层换血**：内部从 XMLHttpRequest 切换到 fetch API，同时新增了 morph 交换和流式扩展。这不是修修补补，是把心脏换了一套。

但真正值得注意的不是技术本身，而是它的发布时机：**正好撞上 Hacker News 当天的技术讨论热点**，最终登上了 HN 热门榜。

这说明什么？

**服务端渲染（SSR）和简化前端这套思路，在 2026 年已经不只停留在小众极客圈了，它已经进入了主流技术话语权**。

## 为什么这件事跟独立博客有关系

我在 8 月 10 日写过一篇关于 CSS 新能力的文章，里面提到了一个趋势：**写博客的人，正在从「用 React 重写一切」转向「够用就好」**。

htmx 4.0 的发布，是这个趋势的另一个信号。

Cloudflare Workers 的崛起、Astro 的流行、htmx 的更新——它们都在说同一件事：**我们不需要 SPA 的复杂度，我们只需要用户能正常访问内容**。

对于独立博主来说，这意味着：

**你不需要会 React，不需要懂 TypeScript，不需要理解虚拟 DOM —— 你可以用你熟悉的 HTML + Python/PHP/任何服务端语言，写一个性能极好、SEO 友好、维护成本极低的博客。**

WordPress 之所以能统治 CMS 市场这么多年，很大一个原因是它不需要你懂代码。但 Astro、htmx 这类工具，正在把「低代码」的门槛从「不需要懂代码」扩展到「不需要懂前端框架」。

## 我的判断

我不认为 htmx 会取代 Astro——两者定位不同，Astro 适合内容驱动的静态站，htmx 适合需要一定交互的服务端渲染应用。

但 htmx 4.0 的发布值得所有独立博主关注，因为它代表了一种**技术价值观**：

**不要为了复杂而复杂。让技术服务于内容，而不是让内容服务于技术的复杂度。**

这个价值观，实际上和独立博客的精神内核是一致的：自己掌控、自己运营、简洁高效。

如果你正在考虑用什么技术搭建博客，除了 Astro 和 WordPress，不妨也了解一下 htmx 这条路。也许它恰好适合你的需求。
