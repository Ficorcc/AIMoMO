每个月我都习惯翻一遍 Web 平台的月度发布清单。这种东西看着无聊，但对折腾主题的人来说，它比任何设计灵感帖都实用——因为它决定了你今晚要不要写那 200 行 JS。

11 月这轮清单里，Chrome 和 Edge 同时到位了四个东西：

- **锚点定位（anchor positioning）**：按另一个元素的位置来摆放元素，典型场景就是"提示框出现在它引用的那段文字旁边"。
- **text-decoration-inset**：CSS 属性，可以调整下划线、上划线、删除线的起点和终点位置——也就是把线缩短、拉长或者挪一挪。
- **HTML setter 方法**：`setHTML()`、`replaceWithHTML()`、`beforeHTML()`、`prependHTML()`、`appendHTML()`、`afterHTML()`，以及对应的 unsafe 版本，用来往现有 DOM 树里插 HTML。
- **HTML-in-canvas**：`<canvas>` 加 `content="drawable"` 后，可以把子元素画进渲染上下文里，同时还能保留可访问性、页面内查找和翻译这些浏览器能力，再叠 2D / 3D 效果。

另外 Firefox 这个月补的是语音识别（SpeechRecognition API 加语法对象），对博客主题影响不大，先放一边。

这篇文章聊前三个——它们恰好都打在博客主题最疼的地方。

## 脚注和悬浮卡：终于能跟 Popper 说再见了

我一直觉得脚注是博客里性价比最高的排版装置，也是实现起来最烦的一个。

要让读者把鼠标放在 `[1]` 上就看到原文出处，传统做法有两条路：一是用 title 属性，丑且不可控；二是引 Popper.js（18KB）或 Floating UI（12KB），然后自己处理视口碰撞、滚动重算、Esc 关闭、翻转到上方还是下方这一整套。

锚点定位把这些活全交给浏览器了：

```css
.footnote-pop {
  position: absolute;
  position-anchor: --fn-1;
  position-area: top span-center;
  position-try-options: flip-block, flip-inline;
}
```

配上 `popover` 属性，打开关闭状态和 Esc 键关闭也是浏览器的事。浏览器自动做视口碰撞检测、自动翻转、祖先滚动时自动重新锚定。

对博客主题来说，这是实实在在的减法：**一个 12KB 起、还要跟着版本升级修的依赖，换成了不到 200 字节的 CSS**。目录浮层、术语注释、图片说明、"复制引用"气泡，全部同理。

## text-decoration-inset：中文排版的细节控有救了

这条我私心最看重。

中文博客里链接下划线一直是个尴尬事。默认下划线会紧贴文字的边界，遇到标点、尤其是全角标点，或者链接末尾带了半角括号，线就会多伸出去一小截，看起来像没对齐。

以前要解决，只能给链接加 `padding` 再调 `text-underline-offset`，或者干脆放弃下划线改用背景渐变——后者遇到换行就露馅。

有了 `text-decoration-inset`，可以直接声明下划线从哪个位置起、到哪里收：

```css
a:not(.no-underline) {
  text-decoration: underline;
  text-decoration-inset: 0.1em 0.1em;
  text-underline-offset: 0.22em;
}
```

线短一点、收得干净一点，一页读下来眼睛会舒服很多。这种改动没有任何人会在评论里夸你，但读者停留时长会告诉你差别。

## HTML setter：评论区和搜索高亮更安全了一点

清单里最有争议的一项是 HTML setter 方法。看到 `setHTML()` 这种名字，大家第一反应都是"又来一个 innerHTML"。

区别在于，这些方法走的是浏览器的 HTML 净化（sanitizer）机制，而且规范里同时列了 unsafe 版本——也就是**安全的选择写在明面上，不安全的也在明面上**。

对博客主题最直接的用途是搜索高亮和评论 / 留言渲染：把命中关键词的那段文本插回 DOM，不用再自己拼字符串、也不容易一不小心拼出 XSS。这个改变很安静，但它把"安全"从个人自觉变成了默认选项。

## 但先别急着删依赖

有一点得说清楚：这批能力是在 Chrome 和 Edge 到位，不等于所有读者都能用。

我的建议是渐进增强，而不是替换：

1. **能用 CSS 做的，就别用 JS 做**。脚注悬浮卡先写 `popover` + 锚点定位，同时保留"点击跳转到文末脚注"这个最原始的兜底——它永远能用。
2. **下划线精修可以放心写**。它只是视觉微调，老浏览器忽略后还是普通的链接下划线，不会坏。
3. **setHTML 用在插入第三方内容的地方**，比如评论。自己写的静态模板没必要为了换语法而改。
4. **实测再上线**。不要相信"支持"两个字，拿 Safari 和 Firefox 各开一遍。锚点定位在老一点的内核上会导致元素直接消失，是最容易翻车的一类特性。

## 我的判断

这两年博客主题的进化方向，大家讨论的多是"更好看"——更大的字号、更克制的配色、更多留白。但我认为真正的进步发生在另一个方向上：**把性能预算从交互库手里抢回来，还给正文。**

一个典型主题现在要加载的 JS 大致是：搜索（Pagefind 算好的，另说）、主题切换、目录滚动高亮、代码复制、图片灯箱、评论加载，再加上浮层的定位库。加完之后 100KB 上下，读者的手机要为此付出几百毫秒。

而 11 月这批特性的共同点是：**它们做的事都是过去必须用 JS 才能做的，而且都是低价值重复劳动**——算位置、防溢出、挪线条。

我的判断是，接下来一年主题圈的竞争点会从"谁的设计更漂亮"转向"谁的 JS 更少、LCP 更稳"。设计可以抄，一页 90KB 的运行时抄不掉。

顺带说一句：如果你在维护一个主题，这件事的收益比新加一个动效大得多。少加载 18KB，比多一个发光按钮，更接近"为读者写东西"。
